流程图驱动项目协作管理软件——产品与技术支持方案

一、产品定位与差异化价值

你的想法在现有项目管理软件市场中具有明确的差异化价值。2026年的主流项目管理工具（如Jira、Asana、monday.com、ClickUp、ONES等）主要聚焦于任务管理、需求追踪和敏捷开发，工作流自定义更多体现在任务状态的流转层面，而非真正的“流程图驱动”。即便支持流程图的工具（如Lucidchart、Slickplan），也更多定位于“流程绘制”而非“流程执行+门禁管控”。

你的产品定位——流程图驱动 + 输入输出物门禁检测 + 文档存储一体化——实际上将“流程设计”和“流程执行”两个通常分离的环节进行了深度耦合。目前市场上的确有大量团队面临类似的痛点：需求在各个系统间流转，协作信息分散在即时通讯工具中，云盘里的文档与项目进度脱节，最终交付时依赖关系难以追溯、变更原因无法复盘。

因此，你的产品差异化价值可以概括为：

1. 流程即执行：流程图不是静态的示意图，而是动态的协作引擎。画完流程图，协作规则即建立。
2. 输出物强制门禁：这不是简单的任务勾选完成，而是通过文档存在性检查来“硬化”流程规范。这正是许多团队在Excel或通用看板工具中无法实现的能力。
3. 低认知负担：流程图天然符合人类对步骤和依赖关系的直觉认知，比表格、列表更直观。

二、核心功能设计

2.1 流程图编辑器（核心交互层）

流程图是整个产品的“指挥中心”，需要同时兼顾绘制便捷性和执行逻辑的严谨性。

节点类型设计：

节点类型 功能 交互特性
普通环节节点 流程的一个执行步骤 点击展开详情面板，显示目标、期限、角色分配、输入输出物
并行子流程节点 内含多个独立并行的子节点 展开后可查看内部子流程图，所有子节点完成后自动汇总
门禁节点 流程关键控制点，强制检查输出物 未通过门禁时，后续节点锁定（灰显/不可操作）
汇总节点 合并多个并行分支的输出 展示所有上游输出物汇总列表
开始/结束节点 流程起止标记 可设置项目总截止日期等全局信息

交互体验设计：

· 拖拽式建图：从侧边栏拖拽节点类型到画布，自动吸附对齐。连线时智能推荐连线路径。
· 点击展开详情：选中节点后右侧滑出属性面板，所有配置项就地编辑，无需弹窗。
· 视觉状态反馈：
  · 未开始：白色背景 + 彩色边框
  · 进行中：渐变背景 + 进度条
  · 已完成：灰色背景 + 勾选图标 + 字体置灰
  · 被阻塞：橙色背景 + 警告图标（门禁未通过）
  · 子流程：节点下方显示“▸ 3个并行任务进行中”等状态条
· 缩放与导航：右下角固定迷你地图（mini-map），单击快速定位。Ctrl+滚轮缩放，空格键拖动画布。
· 快捷操作：右键节点呼出快捷菜单（标记完成/查看文档/分配人员/添加子流程）；双击连线添加备注。

2.2 环节管理（核心逻辑层）

每个环节是一个“卡点”，这是产品规范化的核心机制。

环节状态机：

```
[待启动] ──(前置节点完成)──> [可开始] ──(执行人启动)──> [进行中]
                                                                 │
                                                                 ▼
[已完成] <──(门禁通过+手动确认)── [待确认]
```

门禁检测逻辑：

当一个环节的执行人点击“标记完成”时，系统自动触发门禁检测：

1. 检查所有 required: true 的输出物是否已有有效文档链接
2. 如果是内部文档，检查文档是否真实存在（非空、未删除）
3. 如果是并行子流程的父节点，检查所有子节点是否都已完成且各自的输出物齐全
4. 如果所有检查通过 → 环节状态变更为“已完成”，节点置灰打勾，自动触发流转
5. 如果有检查未通过 → 弹出提示：“以下必需输出物尚未提交：PRD v1.0、技术评估报告。请补充后再提交。”

子流程管理：

· 用户可以在任何普通环节节点上点击“添加子流程”，进入二级流程图编辑器
· 子流程遵循完全相同的规则（卡点、门禁、角色分配等）
· 父节点在子流程视图的左上角显示汇总面板，展示所有子节点的完成状态和输出物汇总
· 所有子流程完成后，父节点自动标记为完成（无需手动确认），但可配置“仍需人工确认”选项

2.3 文档存储服务

文档存储与流程图深度集成，是门禁检测的数据基础。

文档系统功能：

· 项目工作空间：每个项目对应一个独立的文档空间，支持文件夹层级结构
· 版本管理：文档每次更新自动保存历史版本，支持版本对比和回滚
· 在线预览：支持 PDF、Word、Excel、PPT、图片、Markdown 的在线预览，无需下载
· 外链支持：允许关联外部文档链接（如 Google Docs、Figma、Notion），但外链不参与门禁检测
· 权限控制：按角色设置查看/编辑/下载权限，与环节角色自动关联（如“产品经理”角色自动获得 PRD 文件夹的编辑权限）

门禁集成：

· 在环节属性面板的“输出物”区域，用户点击“关联文档”可从文档存储系统中选择文件，或直接拖拽上传
· 系统通过 API 实时检查文档存在性，而不是仅检查链接字符串是否为空
· 当文档被移动到回收站或删除时，关联该文档的环节会收到警告通知

文档门禁检测功能是免费版和付费版的核心区分点：

外链关联 ✓ ✓

2.4 通知系统

自动化通知是确保流程不“卡住”的关键。

通知触发时机：

事件 通知对象 通知内容
前置环节完成 下一环节所有执行人 + 项目负责人 “【需求评审】已完成，请开始【技术方案设计】。截止日期：2026-04-30”
门禁未通过 当前环节执行人 “【技术方案设计】缺少输出物「技术架构图」，请补充”
子流程全部完成 父环节负责人 + 下一环节执行人 “【前端开发】所有子任务已完成，可进入【集成测试】”
截止日期临近 环节执行人 + 项目负责人 “【UI设计】距截止日期还有2天”
环节逾期 环节执行人 + 项目负责人 + 上级管理者 “【后端开发】已逾期3天”

通知渠道：

· 站内通知（默认）：右上角通知铃铛，未读数角标，点击展开通知列表
· 邮件通知（可选）：可配置每日摘要或实时通知
· 企业微信/钉钉/飞书/Teams（付费版）：通过 Webhook 集成
· Slack（付费版）

流程图编辑器方案（核心决策）：

经过对比，推荐以下方案，按推荐程度排序：

🥇 方案一：LogicFlow（强烈推荐）

LogicFlow 是阿里团队出品的国产开源流程图编辑框架，GitHub 10k+ star，专为业务流程图编辑场景设计。

优势：

· 插件化架构（Model-View-Plugin），职责分明，易于扩展和定制
· 前端自执行引擎，支持在浏览器端执行流程逻辑，减少后端依赖
· 支持自定义节点、连线、属性面板，可以完全定制为符合你需求的“环节节点”样式
· 数据驱动，流程图数据以 JSON 格式导出/导入，易于与后端数据库同步
· 官方提供 React / Vue 示例，TypeScript 支持完善
· 国产开源，中文文档齐全，社区活跃
· 支持子流程（SubFlow）概念，天然符合你的并行子流程需求

🥈 方案二：React Flow

React Flow 是国外最流行的 React 图表编辑库，被广泛用于工作流编辑器、低代码平台等场景。

优势：

· 原生 React 设计，API 设计现代化，与 React 生态无缝集成
· 支持自定义节点类型和边类型，灵活性高
· 内置缩放、平移、迷你地图、网格吸附等交互功能
· 实时更新和协作支持良好
· 社区庞大，文档和示例丰富

与 LogicFlow 对比： React Flow 更通用，适合各类图表场景；LogicFlow 更专注于业务流程图和工作流场景，内置了更多流程执行相关的概念（如节点执行状态、条件分支等）。考虑到你的产品核心是“流程图驱动协作”，LogicFlow 的业务针对性更强，且国产背景对国内用户支持更友好。

🥉 方案三：Reaflow

基于 React 的模块化图表引擎，支持构建工作流编辑器和流程图。功能类似 React Flow，但社区规模较小，适合对定制化有极致要求的场景。

画板组件选型建议：

· 如团队 React 经验丰富、需要深度定制 → React Flow
· 如需要快速实现符合中国业务习惯的审批流/工作流 → LogicFlow
· 如团队偏好 Vue → LogicFlow 同样支持 Vue 集成

3.4 流程执行引擎设计

流程执行逻辑的核心数据结构：

```sql
-- 项目表
CREATE TABLE projects (
  id UUID PRIMARY KEY,
  name VARCHAR(255) NOT NULL,
  flow_data JSONB NOT NULL,  -- LogicFlow 导出的完整流程图 JSON
  status VARCHAR(50),
  created_at TIMESTAMP,
  workspace_id UUID
);

-- 节点执行状态表（从 flow_data 中提取并单独管理状态）
CREATE TABLE node_executions (
  id UUID PRIMARY KEY,
  project_id UUID REFERENCES projects(id),
  node_id VARCHAR(100),  -- 对应 flow_data 中的节点 ID
  status VARCHAR(50),    -- pending / in_progress / completed / blocked
  assigned_to UUID[],    -- 执行人 ID 数组
  started_at TIMESTAMP,
  completed_at TIMESTAMP,
  output_artifacts JSONB  -- 输出物列表及验证状态
);

-- 文档表
CREATE TABLE documents (
  id UUID PRIMARY KEY,
  workspace_id UUID,
  name VARCHAR(255),
  storage_key VARCHAR(500),
  version INTEGER,
  node_refs UUID[]  -- 关联的节点执行记录 ID
);
```

门禁检测服务（伪代码）：

```typescript
async function validateNodeCompletion(nodeId: string, projectId: string): Promise<ValidationResult> {
  const node = await getNodeExecution(nodeId);
  const nodeConfig = await getNodeConfig(projectId, nodeId);
  
  // 检查所有必需输出物
  for (const artifact of nodeConfig.outputArtifacts) {
    if (artifact.required) {
      const doc = await getDocument(artifact.docId);
      if (!doc || doc.deleted) {
        return { valid: false, missing: [artifact.name] };
      }
    }
  }
  
  // 如果有子流程，检查所有子节点是否完成
  if (nodeConfig.subFlowId) {
    const subNodes = await getSubFlowNodes(nodeConfig.subFlowId);
    const incomplete = subNodes.filter(n => n.status !== 'completed');
    if (incomplete.length > 0) {
      return { valid: false, incompleteSubNodes: incomplete };
    }
  }
  
  return { valid: true };
}
```

五、界面设计建议

· 配色方案：以白色/浅灰为主背景，节点使用柔和的渐变色（蓝紫渐变、青绿渐变），避免高饱和度颜色造成视觉疲劳

· 流程小人：在连线上方显示一个奔跑的小人图标，表示“流程正在推进”
· 逾期提醒：逾期节点会微微“跳动”并带有感叹号角标，鼠标悬停显示“快点完成我！”
· 空状态插画：新建项目时，显示温馨的插画和引导文案：“画下你的第一个流程图，让协作从此有序。”

六、总结与建议

产品关键成功要素

1. 流程图编辑体验是第一印象：需要做到“拖拽即用、零学习成本”。LogicFlow 在这方面提供了很好的基础，但你需要在上层封装符合自己产品语义的节点类型和属性面板。
2. 门禁检测是核心壁垒：这是你和通用项目管理工具的本质区别。门禁不能只是一个“勾选框”，而必须与文档存储深度绑定，做到真正不可绕过。
3. 文档存储需要足够可靠：作为收费功能的基础，文档存储的稳定性、预览体验、版本管理都直接影响用户续费率。
4. 通知不能泛滥：自动通知是双刃剑，需要让用户可配置通知频率和渠道，避免变成“垃圾邮件制造器”。
