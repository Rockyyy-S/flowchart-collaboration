# 流程图驱动项目协作管理软件
一、产品定位与核心价值
产品定位：流程图驱动 + 强制文档门禁 + 自动流转通知 + 一体化项目文档协作
核心价值：
• 用可视化流程图固化协作规范，杜绝流程混乱、随意跳步
• 以文档门禁强制输出物交付，解决“只干活不留档”问题
• 自动流转与通知，减少沟通成本，责任到人
• 一套系统完成流程设计 + 任务执行 + 文档沉淀 + 进度追踪
二、核心流程与功能设计
1. 项目与流程创建

• 项目立项后，新建项目工作空间
• 提供流程模板库（研发、市场、运营、采购、跨部门协作等），也支持空白画布拖拽
• 流程节点支持：主环节 → 并行子流程 → 子子流程，无限级嵌套
1. 环节（卡点）标准配置

每个环节必填/可选：
• 环节名称、完成目标
• 截止时间、预警提醒时间
• 角色 + 执行人（支持多人/多角色）
• 角色职责说明
• 输入物（自动继承上一环节输出）
• 输出物（可多选：文档类型、数量、是否必填）
• 文档门禁：开启/关闭（开启则无输出物无法完成节点）
• 通知规则：完成后通知谁、超时提醒规则
1. 文档门禁与校验规则

• 输出物支持：
◦ 平台内文档（支持版本管理、预览、评论）
◦ 外链（飞书/钉钉/网盘等）
• 门禁校验：
◦ 开启门禁 → 必须上传/绑定至少一个输出物才能“完成环节”
◦ 支持指定文档类型（PRD、技术方案、测试报告、设计稿等）
◦ 支持必填数量（如必须上传2份文档）
1. 并行子流程机制

• 一个主环节下可添加多个并行子流程
• 子流程相互独立，各自执行人、时间、文档要求可不同
• 所有子流程全部完成 → 主环节自动标记完成
• 子流程同样支持：输入输出物 + 文档门禁 + 通知
1. 状态与视觉交互

• 未开始：正常色
• 进行中：高亮/蓝色
• 已完成：字体变灰 + 打勾标记
• 阻塞/超时：红色提醒
• 子流程完成后自动汇总状态到父环节
1. 自动流转与通知

• 本环节完成 → 自动通知下一环节所有执行人 + 项目负责人
• 通知渠道：站内信 + 邮件 + 企业微信/钉钉/飞书集成
• 附带上一环节输出物链接与当前环节要求
1. 文档存储与工作空间

• 项目级独立文档库
• 按流程环节自动归档输出物，可检索、版本回溯
• 权限控制：项目成员可读、执行人可编辑、管理员可配置
• 文档门禁依赖此模块，为核心收费点
三、界面风格与交互原则
1. 极简现代：浅色为主，强调信息层级，无冗余装饰
2. 流程图画布易用性

◦ 拖拽添加节点
◦ 连线自动吸附
◦ 双击直接编辑
◦ 右键快速配置
1. 零学习成本

◦ 入口清晰：新建流程 → 加环节 → 设人/时间/文档 → 启动
◦ 每个环节卡片悬浮提示
1. 趣味性可选

◦ 完成环节动画
◦ 项目进度条/成就式展示
◦ 支持深色模式/主题切换
四、商业模式
• 订阅制 SaaS
◦ 免费版：流程节点数限制、文档空间小、无门禁校验
◦ 专业版：全功能 + 无限节点 + 文档存储扩容
◦ 企业版：SSO、权限分级、API、定制模板、管理员后台
• 7天全功能试用
• 核心付费点：文档门禁校验 + 更大存储 + 并行子流程 + 高级通知
五、技术选型（前后端分离）
前端
• 框架：React / Vue3
• 流程图引擎：React Flow / Vue Flow + X6（极强可定制）
• UI库：Ant Design / Element Plus
• 文档预览：Office Web / PDF.js / 自建预览服务
后端
• 语言：Java (SpringBoot) 或 Node.js(NestJS)
• 数据库：MySQL + MongoDB（文档元数据）
• 对象存储：阿里云OSS / 腾讯云COS
• 通知：RabbitMQ + 邮件/短信/开放平台webhook
部署与运维
• Docker + K8s 或云托管
• 支持私有部署（企业版收费项）
六、优先级与MVP版本规划
MVP（最小可用版）
• 项目创建 + 简单流程图（无嵌套子流程）
• 环节：执行人、时间、输入输出物
• 基础文档上传与门禁校验
• 环节完成标记 + 简单通知
• 基础进度展示
V1.5
• 并行子流程
• 角色体系与权限
• 文档版本管理
• 企业IM集成通知
V2.0
• 流程模板市场
• 数据统计（耗时、逾期率、文档完整度）
• 审批流增强
• API开放平台
七、差异化亮点（与飞书项目、Asana、Trello 区别）
1. 流程即规则：流程图不是展示，是执行引擎，不能跳步
2. 强文档门禁：不是提醒，是系统强制阻断
3. 天然适合跨团队：流程清晰、责任明确、输出物可追溯
4. 极低上手成本：画流程图=配置项目，不用学任务体系

 八、可直接落地建议
1. 先做研发/交付类项目场景切入（文档多、流程严、痛点强）
2. 流程图编辑器做到足够简单，这是体验核心
3. 门禁规则不要太复杂，先做到“有文档即可通过”，后续再加格式校验
4. 通知一定要及时，否则流转会卡住
