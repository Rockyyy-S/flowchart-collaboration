## 二、产品三大支柱

### 支柱 1：流程图编辑器（交互层）
- **目标** | 让用户在 5 分钟内创建一个完整项目流程
- **核心能力** | 拖拽、连线、双击编辑、右键快捷菜单、缩放导航
- **节点类型** | 5 种 (普通环节、并行子流程、条件分支、汇总、开始/结束)
- **UX 原则** | "一眼看懂流程，细节收在侧边栏"

### 支柱 2：门禁引擎（约束层）
- **目标** | 确保关键输出物不遗漏，流程不"走过场"
- **MVP 支持** | 基础门禁 (文件存在性检查)
- **v1.5 升级** | 规则门禁 (文件数量/大小/格式)
- **v2.0 升级** | 业务门禁 (内容校验/多步审批)
- **核心逻辑** | 点击"完成"时自动校验输出物，不通过则拦截并提示

### 支柱 3：文档存储 + 协作（数据层）
- **目标** | 项目文档的单一事实来源
- **核心能力** | 版本管理、权限控制、在线预览、外链支持
- **与门禁关联** | 实时检查文件存在性（不仅是 URL）
- **收费差异** | Free 版 1GB；Pro 版 50GB；Enterprise 无限

## 五、技术栈快速决策

| 层 | 选择 | 备选 |
|----|------|------|
| **前端框架** | React 18 + TypeScript | - |
| **流程图引擎** | **LogicFlow** (国产优先) | React Flow (备选) |
| **后端框架** | NestJS + Node.js | Java Spring Boot |
| **主数据库** | PostgreSQL | - |
| **缓存/队列** | Redis | - |
| **文件存储** | MinIO (自建) 或 阿里云 OSS | AWS S3 |
| **UI 组件库** | Ant Design v5 | shadcn/ui |
| **样式方案** | TailwindCSS | - |
| **构建工具** | Vite | Webpack |

### 关键技术决策理由

**为什么用 LogicFlow 而不是 React Flow？**
- LogicFlow 是阿里开源，专为业务流程优化，原生支持子流程
- React Flow 社区更大，但需要更多自定义
- **结论** | MVP 用 LogicFlow（快速上线），后续可迁移到 React Flow

**为什么不用 GraphQL？**
- MVP 用 REST API 足够
- GraphQL 复杂查询功能 v2.0+ 再考虑

**为什么不用 Neo4j？**
- 增加系统复杂度和运维成本
- PostgreSQL 的 JSONB 字段足以存储流程拓扑
- 后期如需高级图查询再升级

## 十四、常见问题速查 (FAQ)

**Q: 为什么优先做研发部门而不是通用市场？**  
A: 研发部门流程最复杂、文档最多、付费意愿最高 (⭐⭐⭐⭐⭐)；通用市场虽然大但转化难。

**Q: 基础门禁为什么只检查文件存在性？**  
A: MVP 核心是验证"门禁机制本身有价值"；内容校验太复杂，先验证市场再加。

**Q: 为什么要支持外链但又不参与门禁？**  
A: 降低用户迁移成本 (可先关联 Figma/Notion)；同时激励用户使用自有存储

**Q: 为什么是 3 个月而不是 6 个月？**  
A: 抢占竞争窗口；快速验证假设；融资加速；敏捷迭代反馈。

**Q: MVP 失败会不会前功尽弃？**  
A: 否。即使失败，积累的用户数据、市场洞察、技术方案等都有价值，可用于调整或其他项目。
