# flowchart-collaboration UX/UI 设计规范

> 版本：v1.0 | 日期：2026-04-29 | 负责角色：UX/UI 设计师  
> 适用范围：Web 桌面端（主平台），分辨率基线 1440×900  
> 当前代码基线：`apps/web`（React 18 + Ant Design v5 + TailwindCSS）

---

## 一、体验目标与设计原则

### 1.1 体验目标

| 目标 | 度量方式 |
|---|---|
| **效率**：用户从打开应用到找到目标流程图 ≤ 3 次点击 | 可用性测试路径计数 |
| **清晰**：首次使用用户无需文档即可理解节点状态含义 | 新用户测试任务完成率 ≥ 80% |
| **专注**：画布区域占视口面积 ≥ 65%（默认左侧收起状态） | 布局分区面积比 |
| **反馈**：所有写操作在 300ms 内给出可见响应 | 交互延迟测量 |

### 1.2 设计原则

**P1 — 减法优先**  
去除宣传性文案（Slogan 轮播）、冗余入口（操作同时出现在多个位置）、装饰性动画。每个像素服务于任务，不服务于品牌展示。

**P2 — 工具感，不是门户感**  
对标 Figma、Linear、VS Code 的专业工具风格。深色 Activity Bar + 浅色内容区，用户感知到「在使用工具」而非「在访问网站」。

**P3 — 渐进式披露**  
高频操作（查看流程、点击节点）直接可见；低频操作（团队管理、项目删除）收进二级菜单或 Drawer。不因展示全部功能而造成认知负担。

**P4 — 状态即时可感知**  
节点状态（颜色 + 图标）、加载态（骨架屏）、错误态（内嵌 Alert）均在组件本地呈现，不依赖模态弹窗打断工作流。

**P5 — 操作可逆，破坏操作有护栏**  
删除类操作必须二次确认且说明影响范围；草稿自动保存；批量误操作可撤销（中期目标）。

## 二、目标用户与核心场景

### 2.1 用户画像

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| **项目负责人（Owner）** | 制定流程图、分配节点责任人、追踪整体进度 | 一眼看清全局，快速找到阻塞点 |
| **节点参与者（Member）** | 只负责自己的节点，上传产物、等待审核 | 清楚知道「我该干什么」，操作简单 |
| **只读旁观者（Viewer）** | 了解项目进度，无写权限 | 安静地查看，不被操作按钮干扰 |

### 2.2 核心场景路径

```
场景 A — 项目负责人首次搭建流程
登录 → 创建团队 → 新建项目（绑团队）→ 在项目下新建流程图
→ 进入画布编辑模式 → 添加节点（开始/任务/结束）
→ 设置节点参与者/截止时间/产物要求 → 保存 → 发布

场景 B — 参与者处理自己的节点
登录 → 左侧点击项目 → 点击流程图打开画布
→ 定位到自己的节点（高亮提示）→ 点击节点
→ 在右侧面板查看任务要求 → 上传产物 → 点击完成
→ 等待下游审核通知

场景 C — 下游审核并回退
收到通知 → 打开对应节点面板
→ 第二分区查看上游产物 → 不符合要求 → 填写拒绝理由
→ 点击「拒绝」→ 流程回退，上游节点变为「被回退」状态
```

```
┌─────────────────────┐
│▋ 技术方案评审         │  ← 左侧竖条 = 蓝色（#3b82f6）

  子流程图展开后（悬浮在节点上/下方）：
  ┌────────────────────────┐
  │ 🗂 移动端UI子流程  [跳转] │
  ├────────────────────────┤
  │ 🗂 Web端UI子流程   [跳转] │
  └────────────────────────┘

节点状态色点说明（左侧竖条颜色叠加状态色点）：
  ⏳ 待启动       — 灰色 ○
  🟢 可开始       — 紫色 ◎
```

## 五、交互状态说明

### 5.1 画布交互状态

| 操作 | 视觉反馈 | 时机 |
|---|---|---|
| 悬停节点 | 节点边框加深，右上角出现「⋯」操作按钮 | hover |
| 点击节点（参与者） | 节点出现选中光晕，右侧面板滑入 | click |
| 点击节点（非参与者） | 节点短暂亮起后恢复，无面板（不弹任何提示） | click |
| 拖动节点 | 节点阴影增强、缩放1.05，虚线连接显示可插入位置 | drag |
| 拖动到连线上方 | 目标连线高亮变蓝、显示「插入到此处」 | drag hover |
| 保存中 | 工具栏「保存草稿」按钮显示 loading spinner | saving |
| 保存成功 | 按钮短暂变绿色 ✓，300ms 后恢复 | saved |

### 5.2 节点状态视觉规范

| 状态 | 左侧竖条色 | 状态点 | 说明文字 |
|---|---|---|---|
| PENDING 待启动 | `#e2e8f0`（极浅灰） | ⏳（灰色） | 等待前置节点完成 |
| READY 可开始 | `#a78bfa`（紫） | 🟣（脉冲） | 可以开始，点击分配任务 |
| IN_PROGRESS 进行中 | `#f59e0b`（橙） | 🟠（脉冲动画） | 执行中 |
| GATE_CHECKING 门禁检查 | `#60a5fa`（蓝） | 🔵（旋转） | 系统自动检查产物完整性 |
| COMPLETED 已完成 | `#10b981`（绿） | ✅ | 节点通过审核 |
| NEEDS_FIX 待补齐 | `#fbbf24`（黄） | ⚠（跳动） | 产物不足，需补充 |
| REJECTED 被回退 | `#ef4444`（红） | ✕（红色加粗） | 下游拒绝，需修改后重提 |

### 5.3 模式切换行为

| 操作 | 视觉变化 | 前提条件 |
|---|---|---|
| 切换到编辑模式 | Tab Bar 下方动画展开编辑工具栏；画布网格变深；底部状态栏出现「✏ 编辑中」标识 | 用户角色为 OWNER |
| 切换到查看模式 | 编辑工具栏收起（上滑动画）；网格变浅 | 任意 |
| 非 OWNER 用户 | 工具栏入口不渲染（彻底隐藏，不是禁用） | 前端判断角色 |

```
  背景色   #1e1e2e   — 深色（与亮色内容区形成对比）

  激活色   #ffffff   — 激活图标
  激活块   #4f46e5   — 激活图标背景方块
```

### 6.2 字体规范

```
字体族：
  -apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC',
  'Hiragino Sans GB', 'Microsoft YaHei', sans-serif

字号阶梯：
  10px  — 状态标签、时间戳（极小文字）
  12px  — 辅助说明、Tooltip
  13px  — 侧栏菜单项、表单标签
  14px  — 正文（默认）
  16px  — 面板分区标题
  18px  — 节点名称（大字）、Modal 标题
  24px  — 空态引导大字

字重：
  400  — 正文
  500  — 标签、次要标题
  600  — 节点名、面板标题
  700  — 品牌文字、Modal 主标题
```

### 6.3 间距与圆角

```
间距基准：4px
  4px   — 最小间距（图标与文字）
  8px   — 紧凑元素间距
  12px  — 默认内边距
  16px  — 卡片内边距
  20px  — 面板分区间距
  24px  — 大分区内边距

圆角：
  4px   — 输入框、小标签
  6px   — 按钮、菜单项
  8px   — 卡片、下拉框
  10px  — 面板、节点卡片
  12px  — Modal
  24px  — 用户头像入口（胶囊形）
  50%   — 圆形头像

阴影层级：
  Level-0  无阴影（flat，区分依赖边框）
  Level-1  0 1px 2px rgba(0,0,0,.04)   — 输入框、表格行
  Level-2  0 4px 12px rgba(0,0,0,.06)  — 卡片、侧栏
  Level-3  0 8px 24px rgba(0,0,0,.08)  — 浮动工具栏、节点拖动态
  Level-4  0 16px 48px rgba(0,0,0,.12) — Modal、Drawer
```

### 6.4 动效规范

```
微交互原则：有意义的动画才应该出现

进场：
  Fade-in + translateY(-4px)   0.2s ease-out  — 面板、Popover 出现
  Slide-in-right               0.2s ease-out  — 右侧节点详情面板
  Slide-in-left                0.2s ease-out  — 左侧面板展开
  Scale 0.95→1 + fade          0.15s ease-out — Modal 出现

退场：
  Fade-out                     0.15s ease-in  — 大多数元素消失
  Slide-out-right              0.15s ease-in  — 右侧面板关闭

状态变化：
  脉冲动画（READY/IN_PROGRESS 状态点） — 2s 循环，opacity 0.5→1→0.5
  旋转动画（GATE_CHECKING）           — 1s 线性循环
  颜色渐变（状态切换）                — 0.3s ease，CSS transition

禁止使用：
  超过 0.4s 的页面级动画
  弹跳（bounce）效果（工具感不适合）
  视差滚动
```

### 6.5 图标规范

```
图标库：Ant Design Icons（现有，保持）
图标尺寸：

  20px  — Activity Bar 图标
```

## 七、响应式策略

```
断点定义：
  宽 ≥ 1280px  — 完整三栏（Activity Bar + 侧面板展开 + 画布 + 右侧面板）
  宽 1024-1279px — 默认隐藏侧面板（点击 Activity Bar 图标临时展开，overlay 不推挤画布）
  宽 768-1023px — Activity Bar 收起（改为顶部 Drawer 入口），右侧面板改为底部弹出 Sheet
  宽 < 768px   — 纯移动端（MVP 阶段不需支持，标注为「不支持」即可，加 toast 提示）

最小工作宽度：1024px（加桌面端 min-width 提示）
```

## 八、关键用户旅程与屏幕流

```
首次使用流程（Owner）：

[登录页面]
  ↓ 输入用户 ID → 获取令牌
[主工作区 — 空态]
  ↓ 点击 [+ 新建项目]
[新建项目 Modal]
  ↓ 填写名称 → 创建/选择团队（无团队时先弹团队创建 Modal）→ 命名第一个流程图 → 提交
[主工作区 — 画布空态（新建项目已打开）]
  ↓ Tab Bar 已有「项目名/主流程图」标签，画布提示「编辑模式下双击添加节点」
[画布 — 编辑模式激活]
  ↓ 点击 [✏ 编辑模式]
[编辑工具栏出现]
  ↓ 双击画布 → 选择「🚀 开始节点」→ 填写节点名/产物要求 → 确认
[节点出现在画布上]
  ↓ 继续添加任务节点、结束节点，拖拽连线
[流程图完成]
  ↓ 点击 [💾 保存草稿]
[保存成功 toast，底部状态栏更新节点数]
```

## 九、风险与待确认项

| 类型 | 描述 | 优先级 | 待确认方 |
|---|---|---|---|
| **待定** | Activity Bar 深色方案与左侧面板浅色之间的过渡边界如何处理（硬边 or 渐变） | P2 | 视觉负责人 |
| **待定** | 节点形状改为统一圆角矩形后，原有 START 椭圆/END 同心圆已有用户是否需要迁移提示 | P1 | 产品负责人 |
| **待定** | 全局搜索（⌘K）MVP 阶段是否实现，还是只做占位 | P2 | 产品负责人 |
| **待定** | 通知面板内容依赖后端推送，MVP 阶段是轮询还是 WebSocket | P2 | 后端负责人 |
| **待定** | Activity Bar「搜索」和「通知」在 MVP 阶段是否上线，还是显示「敬请期待」占位 | P2 | 产品负责人 |
| **风险** | 右侧节点面板 slide-in 会导致画布内容被遮盖约 320px，低分辨率屏（1024px）下节点可能被挡住 | P1 | 前端负责人 |
| **风险** | 有分支任务节点（TASK_BRANCH）的子流程图列表展开 UI 在节点密集时可能与相邻节点重叠 | P2 | 前端负责人 |
| **风险** | 深色 Activity Bar + 浅色内容区方案与 Ant Design 默认主题叠加可能有样式冲突 | P1 | 前端负责人 |
| **确认** | 节点统一形状方案需产品确认（从 4 种形状降为 1 种圆角矩形，用颜色语义替代形状语义） | P0 | 产品负责人 |
