## 一、产品简介

### 产品定义

**Flowchart-Collaboration** 是一个流程图驱动的项目协作执行平台，通过流程强约束、文档门禁与自动流转，确保项目不失控、不丢产出、不靠人催。

### 核心价值（三大支柱）

| 支柱 | 价值 | 适用场景 |
|------|------|--------|
| **流程可见** | 项目在哪一步一目了然，进度清晰可追踪 | 大型研发、跨部门协作 |
| **规范保证** | 关键文档必须完成才能流转，防止遗漏 | 合规交付、质量把控 |
| **责任明确** | 每个环节谁负责、交付什么、期限是什么 | 多人团队、绩效考核 |

### 适用范围

| 用户群 | 项目规模 | 最佳实践 |
|-------|--------|--------|
| **研发部 CTO/PM**（优先级 P0） | 20-200 人团队 | 产品开发、研发规范化 |
| **咨询/实施公司**（优先级 P1） | 10-100 人 | 项目交付、多甲方协作 |
| **制造业/硬件研发**（优先级 P2） | 50+ 人 | 需求评审、工程设计、试产 |

## 二、快速开始

### 前置条件

- **Node.js** ≥ 18（推荐 20 LTS）
- **npm** ≥ 9
- **浏览器**：Chrome/Firefox/Safari 最新版本（支持 ES2020 标准）

### 启动步骤

#### 1. 启动后端服务

```bash
# 进入后端目录
cd apps/api

# 安装依赖
npm install

# 启动开发服务（监听 http://localhost:3000）
npm run start:dev
```

**预期输出**：
```
[Nest] 14 - 04/14/2026, 10:30:45 AM     LOG [NestFactory] Starting Nest application...
[Nest] 14 - 04/14/2026, 10:30:46 AM     LOG [InstanceLoader] AppModule dependencies initialized
[Nest] 14 - 04/14/2026, 10:30:46 AM     LOG [NestFactory] Nest application successfully started
Server is running on http://localhost:3000
```

#### 2. 启动前端应用

```bash
# 新建终端，进入前端目录
cd apps/web

# 安装依赖
npm install

# 启动开发服务（监听 http://localhost:5173）
npm run dev
```

**预期输出**：
```
  ➜  Local:   http://localhost:5173/
  ➜  press h to show help
```

#### 3. 访问应用

在浏览器打开 **http://localhost:5173**，进入工作台首页。

## 三、演示流程（完整闭环体验）

### 场景：完成一个 5 步研发流程的某个节点

#### 第一步：创建演示项目

1. 访问 http://localhost:5173 工作台首页
2. 点击 **「一键体验」** 按钮
3. 系统自动创建「演示项目」，包含预设 5 节点流程：
   - 需求评审（必需：PRD）
   - 技术设计（必需：设计文档）
   - 开发（必需：代码审查单）
   - 测试（必需：测试报告）
   - 发布（必需：发布检查清单）

**预期结果**：跳转到项目详情页，流程画布中显示 5 个 READY 状态的节点。

#### 第二步：启动第一个节点（需求评审）

1. 在流程画布中，点击 **「需求评审」** 节点的卡片
2. 右侧抽屉打开，显示节点详情：
   - 节点名：需求评审
   - 当前状态：READY（蓝色)
   - 必需产出物：PRD v1.0 ✗（待补齐）
   - 按钮：开始执行、…

3. 点击 **「开始执行」** 按钮
4. 节点状态变为 **IN_PROGRESS**（黄色）

**预期结果**：卡片颜色变黄，按钮列表更新（出现"提交完成"按钮）。

#### 第三步：尝试直接提交（门禁失败演示）

1. 保持抽屉打开，直接点击 **「提交完成」** 按钮
2. 系统检查必需文档...
3. 检查结果：**❌ 需求评审失败**
   - 缺失文档：PRD v1.0
   - 节点状态变为 **NEEDS_FIX**（红色脉冲）
   - 提示文案："请补齐缺失的产出物后重新提交"

4. 抽屉中"必需产出物"列表红色文字"PRD v1.0"行高亮显示，附 **「补齐」** 按钮

**预期结果**：流程画布中"需求评审"节点变为红色脉冲动效；抽屉内文档列表标记缺失。

#### 第四步：补齐文档（绑定演示）

1. 在抽屉中，点击 PRD v1.0 行的 **「补齐」** 按钮
2. 弹出 **「上传与绑定文档」** 对话框
3. 选择文件或填写外链（演示）：
   - 本地上传：选择任意 PDF/Word（文件名示例：`PRD-v1.0-2026.docx`）
   - 或外链：输入 `https://example.com/prd.pdf`

4. 点击 **「上传并绑定」**
5. 确认消息："✓ 文档已关联，可重新提交"

**预期结果**：对话框关闭，抽屉中 PRD v1.0 行恢复正常显示（不再红色高亮）。

#### 第五步：重新启动与通过门禁

1. 抽屉中显示节点状态为 **NEEDS_FIX**（红色）
2. 点击 **「重新开始」** 按钮
3. 状态变为 **IN_PROGRESS**（黄色）
4. 点击 **「提交完成」** 按钮
5. 系统再次检查文档...
6. 检查结果：**✓ 需求评审通过**
   - 节点状态变为 **COMPLETED**（绿色）
   - 自动扫描后继节点，**「技术设计」** 状态从 READY 变为 PENDING（等待前置完成）

7. 页面顶部统计更新：完成进度 1/5 → 2/5

**预期结果**：
- 节点卡片变绿（COMPLETED）
- 后续节点按逻辑展开
- 可继续点击下一个节点，重复步骤 1-5

## 五、常见问题与排查

### Q1：浏览器访问 http://localhost:5173 显示"无法连接"

**可能原因**：
- 前端服务未启动
- 前端启动失败（依赖缺失、端口被占用）

**排查步骤**：
```bash
# 1. 确认终端输出中是否有错误
# 查看是否有 "error" 或 "ERR!" 字样

# 2. 确认前端启动方式
cd apps/web
npm run dev

# 3. 若端口被占用，启动时会提示
# 预期输出应包含 "Local: http://localhost:5173"

# 4. 清缓存并重启（如有旧进程）
npm run dev -- --force
```

---

### Q2：页面加载后报错"连接后端失败"

**可能原因**：
- 后端服务未启动
- 后端启动在错误的端口（不是 3000）
- 防火墙阻止

**排查步骤**：
```bash
# 1. 确认后端运行状态
cd apps/api
npm run start:dev

# 2. 验证后端是否监听 3000
curl -i http://localhost:3000/api/v1/projects

# 预期应返回 HTTP 200 或 400+（不是连接拒绝）

# 3. 若返回连接拒绝，检查后端是否有启动错误
# 查看终端输出，搜索 "error" 或 "ERR!"
```

---

### Q3：点击"一键体验"后仍是空白或报错

**可能原因**：
- 前后端通信中断
- 浏览器控制台有 JavaScript 错误

**排查步骤**：
```bash
# 1. 打开浏览器开发者工具（F12 或右键 → 检查）
# 2. 切换到"控制台"标签
# 3. 查看是否有红色错误信息，记录完整错误文本

# 常见错误：
# - "Failed to fetch: http://localhost:3000/api/v1/projects"
#   → 后端未启动或响应超时
# - "SyntaxError: Unexpected token..."
#   → 后端返回非 JSON，可能是 error page
# - "CORS error"（如果有）→  代理配置错误

# 4. 尝试手动创建项目
curl -X POST http://localhost:3000/api/v1/projects \
  -H "Content-Type: application/json" \
  -H "x-user-id: user-001" \
  -d '{"name":"测试"}'

# 应返回 JSON，可确认后端工作状态
```

---

### Q4：节点状态显示为"PENDING"而非"READY"

**原因**：
- 这是正常的。项目初始化时，除第一个节点外，其他节点默认为 PENDING（等待前置节点完成）
- 当前置节点状态变为 COMPLETED，后继节点自动变为 READY

**或可能的异常**：
- 后端与前端数据不同步（某个请求失败但前端未刷新）
- 解决：按 F5 刷新页面或点击"刷新"按钮

---

### Q5：选择文件后上传显示"格式不支持"或卡住

**排查步骤**：
```bash
# 1. 检查文件大小（MVP 限制 100MB 以内）
# 2. 检查文件格式（支持：PDF / Word / Excel / 纯文本）
# 3. 确认网络连接正常（看浏览器控制台 Network 标签）

# 4. 查看浏览器控制台是否有上传错误
# 常见：
# - 413 Payload Too Large → 文件超过后端限制
# - 400 Bad Request → 文件格式未识别（后端应报详细错误）
```

---

### Q6：关闭"节点详情抽屉"后，页面仍显示旧状态

**原因**：
- 前端缓存未及时更新

**解决**：
- 关闭抽屉后，画布会自动刷新执行状态列表（预期 1-2 秒）
- 若 5 秒后仍未更新，刷新页面或进入浏览器控制台检查报错

## 六、已知限制与 MVP 约束

| 限制项 | 情景 | 预期行为 | 发布版本 |
|-------|------|--------|--------|
| **LogicFlow 占位实现** | 在流程编辑器中拖拽节点、调整位置 | 仅支持列表式节点显示（不支持拖拽重新排列） | v1.0 |
| **流程画布为列表式** | 访问流程画布希望看到有向图可视化 | 当前为纵列节点卡片排列，适配 MVP 快速验证 | v1.0 |
| **后端无项目列表接口** | 在工作台刷新或切换浏览器后丢失项目列表 | 项目数据存储在浏览器 localStorage，跨浏览器不可见 | v0.2 |
| **所有节点初始 READY** | 期望复杂前置依赖关系（非线性流程） | 当前 MVP 仅支持单线性流程，所有节点初始化为 READY（后续改为按前置节点决定） | v1.0 |
| **无 JWT 鉴权** | 多人场景中身份伪造风险 | MVP 使用请求头 `x-user-id` 模拟用户身份（仅用于审计和日志，不作为安全边界） | v0.2（生产） |
| **无 Rate Limiting** | 接口被高频调用 | 当前无限流保护，生产版本会加入 API 限流 | v0.2（生产） |
| **无实时通知推送** | 关闭页面后有新事件 | 当前仅支持站内通知（取决于用户是否打开页面），邮件通知计划中 | v0.2 |
| **文件存储为内存模拟** | 服务重启后丢失所有数据 | MVP 使用内存存储，仅用于演示和测试，生产环境需切换 PostgreSQL + MinIO/OSS | v0.2（生产） |

## 七、最佳实践建议

### 流程设计

✅ **推荐**：
- 3-8 个节点的线性流程（符合 MVP 设计）
- 清晰的必需产出物定义（避免歧义）
- 为每个节点设置合理的 due date

❌ **不推荐**：
- 超过 20 个节点的复杂流程（当前版本性能未优化）
- 循环/并行节点（v1.0 才支持）
- 嵌套条件门禁（v1.5 才支持）

### 文档管理

✅ **推荐**：
- 为每个必需产出物设置统一的命名规范（如 `PRD-v1.0.docx`）
- 定期清理已过期的文档版本（保留最新 3 个版本）
- 使用外链时确保 URL 长期有效

❌ **不推荐**：
- 上传超大文件（>100MB，会影响系统性能）
- 频繁修改已绑定文档的内容（会破坏追溯链）
